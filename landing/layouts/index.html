test_books.pyPYTHON
import opensearchpy
from openmock import openmock

@openmock
def test_find_a_book():
    client = opensearchpy.OpenSearch()
    client.index(
        index="books", id="1",
        body={"title": "Dune"},
    )
    result = client.search(
        index="books",
        body={"query": {
            "match": {"title": "Dune"}
        }},
    )
    assert result["hits"]["total"]["value"] == 1
✓ test_find_a_book PASSED

01 / THE WORKFLOW

Write the test around
what your application does.

  1. 01

    Decorate the test

    @openmock patches client constructors for the decorated call. Construct your client inside that scope.

  2. 02

    Exercise a workflow

    Index documents, run supported queries, and update or delete records. Later calls see the state left by earlier calls.

  3. 03

    Assert the result

    Check your application’s outcome using familiar OpenSearch-shaped responses. Each decorated call starts with fresh client caches.

02 / A DELIBERATELY SMALL FAKE

Fast feedback for
everyday document flows.

Use the mock where a small, predictable model is enough. Keep real-server tests for the behavior that needs OpenSearch.

Explore the supported API →

Documents & queries

CRUD, bulk, search, count, pagination, and scrolling. Selected term, match, range, bool, and aggregation behavior.

Sync & async tests

Fake clients for both programming styles. Core document workflows are shared; sub-client coverage differs.

A clear boundary

No relevance engine, full analyzer pipeline, distributed execution, or complete Painless runtime. Verify those with a real cluster.
